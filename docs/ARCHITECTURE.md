# nim — Marathon アセットビューワー 設計書

対象: Bungie『Marathon』(2026, PC/Steam 版, Tiger エンジン系。tiger-pkg 内のコード名は "Goliath")
言語/基盤: C++23 / MSVC / CMake / Direct3D 12 / Dear ImGui(予定)

## 1. 目標と非目標

**目標**

- ゲーム内の **テキスト・セリフを漏れなく** 取得する(参照を辿るのではなく、全パッケージの全エントリを総当たりで分類する)。
- 3D アセット(静的メッシュ、エンティティ、スケルトン)、マップ、テクスチャ、音声、動画を閲覧・書き出しする。
- **ゲーム本来のシェーディングを再現**する(ゲームの DXBC シェーダをそのまま D3D12 で実行する)。
- 30GB / 650 ファイル規模を前提に、起動・検索・表示が速いこと。

**非目標 / 守ること**

- 起動中のゲームプロセスには一切触れない(BattlEye があるため、メモリ読みやフックはしない)。インストール済みファイルを読み取り専用で開くだけにする。
- ゲームデータや `oo2core_9_win64.dll` を再配布しない。DLL はユーザーのインストールから実行時にロードする。
- 書き出したデータの再配布支援はしない(個人の閲覧・研究・アーカイブ用途)。

## 3. 全体構成

```
nim_app (ImGui UI) ─┬─ nim_render (D3D12)
                    ├─ nim_content (形式ごとのデコーダ)
                    ├─ nim_index (全文検索・参照グラフ・キャッシュ)
                    └─ nim_schema (クラスハッシュ → 構造体定義)
                              │
                         nim_core (パッケージ I/O)          nimcli (バッチ/検証/書き出し)
```

各層は下の層にしか依存しない。`nim_core`〜`nim_content` は GPU にも UI にも依存しないので、CLI とテストからそのまま使える。

### 3.1 nim_core — パッケージ I/O【実装済み】

- `MappedFile`: パッケージはメモリマップで読む(syscall とコピーを避ける)。
- `Package`: ヘッダ、エントリ、ブロック、named tag、hash64 のパース。ブロック単位の「復号 → 展開」パイプライン。パッチを跨ぐブロックは `<name>_<patch>.pkg` を遅延で開く。
- `PackageCipher`: Windows BCrypt の AES-GCM(外部ライブラリ不要)。
- `PackageManager`: install の自動検出(Steam ライブラリ)、最新パッチの選択、言語選択、TagHash / TagHash64 の解決。
- 今後: ブロック LRU キャッシュ(展開済み 256KiB 単位)、スレッドプールでの並列デコード、redacted ブロック用の外部鍵(`keys.txt`)。

### 3.2 nim_schema — タグ構造の型付け

Tiger のタグ(8/0)は「先頭 u64 = サイズ、以降は固定レイアウト + 相対オフセットの配列 / 文字列 / TagHash 参照」という自己記述性の低い形式で、`ref` がクラスハッシュになっている。

- **宣言的スキーマ**: クラスハッシュごとにフィールドのオフセット・型・配列要素型をテーブルで定義する(C++ のマクロ/constexpr テーブル + 実行時に読める JSON の二本立て)。ゲーム更新でオフセットが動いても、コードを書き直さずに定義だけ差し替えられるようにする。
- スキーマは **ビルド ID(ヘッダ 0x28 / 0x18)ごとにバージョン管理** する。Deimos が 1.1.0 で TFX opcode 変更により壊れた事例があるので、更新耐性を最初から設計に入れる。
- **リバースエンジニアリング支援**: 未知クラスに対して、配列ヘッダ候補・TagHash 候補(`0x808xxxxx`)・float 候補・文字列候補を自動で注釈する「タグエクスプローラ」を UI と CLI の両方に用意する。600 種のクラスを人力で埋めていくための道具がこのツールの土台になる。

### 3.3 nim_index — 全件インデックス

- 初回起動時に全エントリのメタデータ(TagHash, type, class, size, パッケージ)と参照グラフ(タグ本文中の TagHash を走査)を作り、`%LOCALAPPDATA%/nim/<build>.nimidx` に保存する。2 回目以降は mmap するだけで即座に起動できる。
- 文字列インデックス: 全言語の全ローカライズ文字列を `string_hash → 各言語のテキスト` で保持し、n-gram の全文検索に対応する(日本語を含む)。
- 逆参照(この文字列 / テクスチャを使っているのは誰か)を引けるようにする。

### 3.4 nim_content — 形式ごとのデコーダ

| 対象 | 方針 |
|---|---|
| テクスチャ | 32/1 ヘッダ(DXGI フォーマット, 寸法, mip, `large_buffer` TagHash)+ 40/1 or 48/1 データ。BC 圧縮はデコードせず GPU に直接上げる。書き出しは DDS(無変換)/ PNG(DirectXTex) |
| ジオメトリ | 頂点/インデックスバッファ(32/40 の 4, 6)+ メッシュタグ(パーツ, LOD, マテリアル参照, 量子化パラメータ)。スケルトン/スキニング。書き出しは glTF 2.0 |
| マテリアル | Technique タグ(ステージごとの DXBC 参照, テクスチャスロット, サンプラ, cbuffer, **TFX バイトコード**) |
| マップ | Activity → Bubble/Map → Static instances / Entity 配置 / Terrain / Decal / Light / Cubemap。数十万インスタンスを前提にする |
| テキスト | ローカライズ文字列コンテナを **総当たりで全列挙**(参照を辿るだけだと孤立した文字列を取りこぼす)。`cipher_shift` の扱いを検証する。全言語を並べて表示 |
| セリフ | ダイアログテーブル(話者, 文字列ハッシュ, WEM / Wwise イベント)を辿り、「字幕テキスト + 話者 + 音声」を 1 行で見られるようにする |
| 音声 | BNK の HIRC を解析してイベント → サウンド → WEM の対応を作る。WEM(Wwise Vorbis/Opus)は vgmstream 相当のデコーダで WAV / OGG にする |
| 動画 | 27/1(USM 推定)を取り出し、外部の ffmpeg で再生/変換する |
| アイテム | investment 系パッケージ(`w64_investment_*`)の定義を表形式にする |

### 3.5 nim_render — D3D12 レンダラ(シェーディング再現の要)

既存ツールのシェーディングが不正確なのは、ゲームのシェーダを捨てて汎用 PBR で描き直しているから。nim では **ゲームの DXBC をそのまま D3D12 パイプラインに渡す**。

1. **シェーダ**: 41/x の DXBC から PSO を作る。リフレクション(RDEF/ISGN/OSGN)で入力レイアウト、cbuffer、テクスチャスロットを取得し、ルートシグネチャを自動生成する。
2. **TFX バイトコード VM**: マテリアルの cbuffer の値はタグ内のバイトコード式で計算されるので、これをインタプリタで実行して cbuffer を埋める。opcode 表はビルドごとのスキーマに入れる。
3. **スコープ(グローバル cbuffer)**: view, frame, 光源, 大気, 露出などエンジンが供給する定数を再構築する。ここの精度が見た目を左右する。シェーダのリフレクション情報から必要なメンバを洗い出し、意味を一つずつ特定していく。
4. **パス構成**: Tiger の deferred 構成(G-buffer → ライティング → 透過 → ポスト)を再現する。未解明の段階は自前の PBR で代替し、**元シェーダ / 代替の切替と G-buffer の各チャネル表示**をデバッグ表示として用意する。
5. **性能**: bindless ディスクリプタヒープ、コピーキューでの非同期アップロード、テクスチャのストリーミング(mip 単位)、マップのインスタンシング、GPU カリング。

検証方法: ゲームにはデバッガやキャプチャツールを接続できない(BattlEye)ので、同じ視点の **ゲーム内スクリーンショットとの比較** で詰める。

### 3.6 nim_app — UI

Dear ImGui の docking を使う。

- パッケージ / クラス / 種別のツリー、全文検索(テキスト・ハッシュ・TagHash)
- タグエクスプローラ(hex + スキーマ注釈 + 参照の行き来)
- モデル / マップビューワー(元シェーダ ↔ 代替、G-buffer 表示、ライティング切替)
- テキスト / セリフブラウザ(言語並列表示、音声の再生)
- 一括書き出し(glTF, DDS / PNG, WAV / OGG, 文字列の CSV / JSON)

### 3.7 nimcli【一部実装済み】

`pkgs`, `ls`, `types`, `read`, `verify` は実装済み。今後 `strings`(全テキストのダンプ)、`export`、`index` を追加する。UI と同じライブラリを使うので、回帰テスト(全ブロック復号、全文字列件数)にも使う。

## 5. リスク

- **ゲーム更新でクラスハッシュ・オフセット・opcode が変わる** → ビルドごとのスキーマと、全件の回帰テスト(`verify` + 件数チェック)で検知する。
- **redacted ブロック**(未公開コンテンツ。グループ鍵が必要)→ 現時点では 0 件。鍵がなければ読めないことを UI に明示する。
- **言語パッケージ**: 現在の install には en / jpn だけがある。ほかの言語は Steam でその言語を選んで追加 DL した場合に読める。
